# Demon 游戏设计规范

Updated: 2026-10-25 Asia/Shanghai
状态：已确认设计基线，尚无游戏实现。工程实况见 [ARCHITECTURE.md](ARCHITECTURE.md)，拟实施方案见 [TASK-002](Tasks/TASK-002-playable-slice.md)。

## 1 定位与约束

第一人称雪地恐怖解谜。玩家独自在监测站值守，在九天内观察石板、理解符文规则、监测与诱导恶魔投影，最终尝试封湖，却因误读时间循环重新打开封印。保留原案的监测站、湖岸、工具棚、雪林与遗迹方向，不采用无线电求救者身份骗局。

用于课程展示，制作周期剩余三周，实际提交日期待定。团队为策划一名、技术美术一名，Codex 负责程序与技术。游玩总时长没有固定指标；不能简单按九天乘24分钟作为目标时长。

第一人称键鼠已确认；Windows 独立运行版是后续建议，最终展示设备与构建目标待确认。不要把本机 Windows 等同于平台需求已定。

## 2 故事与威胁

第一天夜晚的暴风雪中，邪教徒开启湖中封印，五块封印石板散落。此后恶魔投影可以影响现实，但没有正式降临的实体。主角原定第八天由他人接班，接班未到的原因待定。

恶魔配合制造争夺最终石板的假象。投影不能造成玩家伤害，但会在雪地追逐。玩家看不到追逐者完整实体，只能看到巨大脚印接近，并听见声音。投影可影响现实，因此废止旧案“所有脚印都无压痕、所有现实对象都不能受影响”的统一限制。

照明干扰、诡异声音、黑影突脸等为已提出的恐怖表现方向；具体天数、位置、次数与演出由策划后补，不自行编成正式关卡。被追上后的无伤反馈，以及投影能影响哪些实物、为何不能自行重构石板，仍待确认。

发现引导与程序执行分离：不以玩家捡到、靠近或读过石板作为已有固化日期程序运行的前提。引导石板的发光不等于世界中可转移的 LIGHT 数值。

## 4 世界时间与条件调度

- 一天暂定现实24分钟，对应游戏内24小时；日长和每天醒来时刻留可调参数。
- 日期条件在满足范围内每天最多执行一次，当日最早触发时刻是零点。
- 当天零点过后才形成的有效程序，若条件已满足，立即执行并记录当日已触发。T07在D8补全后因此立即生效，无需另加“手动破例”。
- 自然流逝、睡觉、WHILE 的 +1 均经过同一个世界时钟，跨过的零点事件必须正常处理。
- IF 本次执行后结束；若日期条件仍在范围内，后续日期可获得新的当日资格。不是旧版“激活一次后永不再参与日期调度”。
- 最终 WHILE 完成本轮后经过 +1，推进到下一天00:00再判断。这是当前接受的时间推进计划，加速曲线和阅读过渡可后续调整。
- 同一 T07 的下一轮由正在运行的循环接管，不能再被每日调度执行一次。
- 玩家可以不探索、连续睡至D9；不锁睡觉要求完成任务。每天醒来时刻依流程变化，具体表待定。

`+1` 当前表示下一天零点，不是当前时刻加24小时。它属于返回线路明确的时间操作，不意味着任何 WHILE 都自动拥有时间能力。

## 5 固定拓扑与函数

石板为九宫格，行优先编号1至9。当前示意布局：1=9，2=比较符 >=，3=DAY，4空，5=EXCHANGE，6=+1，7=SEAL，8=箱子，9=湖。

- IF 路径：`3 -> 2 -> 1 -> 5 -> 7 -> 8 -> 9`。
- WHILE 在此基础上加返回：`9 -> 6 -> 3`，6号位为 +1。
- 上排含义为 `9 >= DAY`，即 `DAY <= 9`。不要因为遍历方向把条件写反。
- 函数必须处在 IF、ON 或 WHILE 等条件结构中，不提供玩家可直接使用的裸 CALL。
- TRANSFER 从提供对象向接收对象转移一单位，双方原子更新，检查来源、支持属性和容量。
- EXCHANGE 交换两个对象同一属性的全部值，重复一次会恢复原状态。
- 可以使用 OPEN 等专用函数，参数签名按用途定义，不强制所有函数填满相同数量的槽位。
- ON 的具体对象绑定、监听条件和复位方式随两块工具确定，不能先假定旧 v0.2 布局全部保留。

不实现任意曲线识别、玩家绘线、通用未来模拟或四维时间片段拼合。旧版同帧即时 WHILE 与四轮上限不适用于本次最终时间循环。

## 6 石板编辑与程序固化

前六块已经固化，只有T07尚未完成。所有线路由石板自带；T07只放置、补全、移动符文，预置提示符文也可移动。错误组合允许反复尝试；首版只接受目标程序。

完整目标通过后，线路熔断，将程序固化在石板内部，原线路不能再次写入。之后即使抠下表面符文，内部程序仍继续运行；不存在另一个可有效重写的空白石板。不提供拆改或中止最终循环的玩法。

错误或非目标组合不固化、不改变世界。抽象语言上合法但不是本关目标的组合，不能一律提示为语法错误。BOX与LAKE对调是否视为等价目标、预置清单、干扰符文与具体检查手势待定。前六块实际抠符文的操作表现是否制作待定，不影响已确认的固化规则。

## 7 箱子 湖与结局

SEAL 是封印或锁定属性，1封闭、0解封；箱盖机械开合是另一种表现状态，手动掀盖不能改变SEAL。

| 节点 | BOX.SEAL | LAKE.SEAL | 结果 |
| --- | --- | --- | --- |
| D8重构前 | 1 | 0 | 箱子锁住，湖维持第一夜开启 |
| D8第一次交换 | 0 | 1 | 箱子解封，湖重新封印 |
| D9第二次交换 | 1 | 0 | 箱子封闭，湖重新开启 |

箱内文本揭示 WHILE、+1 与真相。玩家以为是IF，却实际完成WHILE。返回过程伴随世界加速变黑，到D9 00:00再次交换。实体已赋予且湖处于开放，恶魔才正式降临。

建议从第一次交换后开始可调整的阅读过渡与时间加速，不只以玩家关闭文本界面作为时间变化原因。提前退出和一直阅读的表现待样例确定。线路和+1必须事先存在，不在揭示时凭空添加。

若没有重构T07：原OPEN破碎无效，但湖本来就从第一夜开启；D9实体程序仍运行，直接触发降临。无需自动补齐碎片、额外隐藏OPEN或安全结局。

游戏在D9降临结束。若循环继续，D9动作后还会+1至D10，条件才不成立；不能声称它自然结束于D9。终局必须停止后续推进与交换副作用。

## 8 编辑体验与制作表面

石板在场景中近距离操作；交互后拉近镜头，不另做独立二维拼图世界。移动锁定、鼠标显示、退出方式与具体键位待实现样例选择，参数可调。

场景、碰撞、摄像机位置、灯光、材质、音频、粒子和静态UI由保存的Scene、Prefab或对应资产维护。程序实现规则与状态驱动，不在启动时重建整间房屋或静态UI。日长、醒来、语句、槽位、交互距离、镜头、追逐与加速节奏提供可编辑配置。

## 9 非目标与待定

非首版必做：战斗/伤害/死亡、复杂生存数值、自由画线、通用语言解释器、多条自由编程结局、中止循环分支。暂停、音量、存档/继续、展示重置和内部跳日工具属于建议，范围待确认；不要把工程模板Attack/Jump等动作当成玩法已批准。

优先待定：

1. T04实体赋予方式与来源，投影现实影响边界，以及不能自己修石板的理由。
2. T05/T06条件、激活、再监听与复位，工具可重复操作与日期“每天一次”的关系。
3. 最终预置/缺失/干扰符文、参数对调是否接受、目标验证与固化手势。
4. 箱子文本与阅读动机、接班未到原因、邪教徒线索、原第五封印OPEN在首夜已开湖前提下的叙事用途。
5. 醒来时间表、普通文本是否暂停、最终阅读过渡与加速长度、追上后的无伤反馈和惊吓脚本。
6. 目标展示设备、平台、提交日、存档与设置范围。
